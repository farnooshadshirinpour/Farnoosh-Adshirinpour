Interactive Spatial Drawing Assistant

A prototype that measures how accurately a person draws in a 3D scene, and gives feedback while they draw.

  • Unity 6engine
  • C#language
  • 4 × 4unit target rectangle
  • Livefeedback while drawing

How it works

1

Draw

The user traces the four sides of a predefined rectangle in a 3D scene, using the mouse.

2

Measure

Each stroke is compared with its target edge in 3D coordinates, and the deviation is recorded.

3

Respond

Deviation and suggestions are reported in real time, while the stroke is still being drawn.

The prototype treats drawing as an interaction that a system can represent, measure, and support. It carries the perspective, form, and depth I work with as a painter into a computational setting, and is a first step toward investigating how real-time feedback can support spatial drawing.

Method

  1. The scene defines the target as four points on one plane. Each side is 4 Unity units long.
  2. The user draws each edge with the mouse. Strokes are captured as point sequences and rendered with Unity’s LineRenderer as a separate UserDrawing line, so the drawn stroke stays visually distinct from the target.
  3. The system measures the Euclidean distance between the drawn points and the corresponding target edge in 3D coordinates.
  4. For each edge it records average and maximum deviation. The average describes overall accuracy, and the maximum exposes local errors that the average hides.
  5. Corner-tolerance checks and side-completion detection track whether the user is progressing through the rectangle in order.

Observations from testing

I tested the prototype with my own drawing attempts, logging deviation for each edge and refining the interaction between sessions.

10.0 cmmaximum on the same edge: one large error that the average hides
3.7 → 9.4 cmaverage on edge BC, from test 1 to test 2
N1

Average and maximum capture different things

In the first test, edge CD had an average deviation of 2.1 cm but a maximum of 10.0 cm. A stroke can be accurate overall and still contain a single large error, which an average alone would conceal.

N2

Reaching a target is not following the path

In some attempts the system advanced to the next side as soon as the stroke reached a corner, even when the preceding stroke had drifted from the path. Completion checks therefore need to consider the movement as well as the endpoint.

N3

Accuracy varied between attempts

Edge BC averaged 3.7 cm in the first test and 9.4 cm in the second, and its maximum rose from 7.0 cm to 13.0 cm.

Where I want to take it next

With other people. Run a small study that compares drawing with and without real-time feedback.

Inside the scene. Show the feedback visually in the 3D scene instead of in the console.

Beyond one plane. Move from a mouse on a flat target to free strokes in 3D space.

These are directions I want to explore. They are not built yet.
